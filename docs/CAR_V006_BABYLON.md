# Проверка CR Sport 01 v006 в Babylon.js

Открыть: [просмотр машины](https://testmovielucky.github.io/coastal-racer/?view=car-v006). Основной физический стенд остаётся по исходному адресу.

## Результат локальной проверки, 2026-09-09

В движок загружен настоящий принятый GLB, SHA-256 `ada35c65b99507aa1f019be017b2c7d0ba3f9e222bc7e496686e13539c7c38dd`. Файл не изменён. Художественное принятие по Blender-рендерам записано в acceptance.json; новый просмотр не означает автоматическую художественную приёмку в Babylon.

| Проверка | Результат |
|---|---|
| Импорт Babylon 9.25.0 / glTF loader 9.25.0 | Успешен |
| Геометрия | 21 114 треугольников, 16 отрисовываемых primitive-мешей |
| Габариты в движке | 2.254 × 1.215 × 4.468 м (X/Y/Z) |
| Материалы | 4 PBR-материала; исходные параметры, clearcoat и COLOR_0 сохранены |
| Колёса | Все четыре имени сохранены; вращение вокруг локальной X не смещает pivot |
| Перекраска | Меняется Body_Paint, можно вернуть исходный цвет |
| Коллайдер | Отдельный GLB показывается проволочной рамкой; это визуальная проверка без Havok |
| Ракурсы | За машиной, сзади, спереди, сбоку; мышью/пальцем можно вращать обзор |
| Загрузка | Только локальные ресурсы; SHA-256 проверяется перед импортом |
| Рендер | В типичных проверенных кадрах 17 draw calls с одной машиной и полом |

Колёса имеют небольшие элементы с Body_Paint: их цвет меняется вместе с кузовом по исходному материалу. Исходные doubleSided и настройки материалов сохранены. Автоматическое объединение мешей и оптимизация модели не проводились.

## Освещение и границы проверки

Один направленный свет, слабое заполнение и простая процедурная cubemap 32×32 на грань, созданная локально до показа. Это тестовая настройка для оценки PBR, не финальное освещение побережья. HDRI из сети, тени, bloom и другие тяжёлые эффекты не подключены. Цвет/блики закономерно отличаются от Cycles. Поверхности и швы остаются такими, как в принятом GLB.

Игра не получила новый контроллер, ботов или физическую машину. В просмотрщике одна машина стоит на месте; переключатель колёс показывает анимацию узлов. Нет замера полной гонки с шестью такими автомобилями. Камера здесь показывает желаемое направление сзади, но ещё не сопровождает движущийся автомобиль.

Проверки выполнялись на Windows в Chrome с программным SwiftShader: эти FPS **не являются** результатами iPad/iPhone. На устройстве открыть страницу, осмотреть ракурсы/цвет/колёса и выгрузить «Отчёт JSON». В отчёте есть параметры модели, PBR, версия, браузер/рендерер, canvas, интервалы кадров и CPU work. Замеры после паузы не включают время простоя.

## Воспроизведение

- `tools/npm.ps1 run build` — typecheck и production; проверяются хеши обоих GLB и состав dist.
- `tools/npm.ps1 test` — 7 тестов логики/физики основного стенда.
- `tools/npm.ps1 run test:e2e` — 29 успешных, один неприменимый desktop-тест ориентации пропущен. Включает 12 проверок просмотрщика на ПК/телефоне/планшете.
- После исправления кадрирования: `node node_modules/@playwright/test/cli.js test carPreview --grep 'accepted v006 renders'` — ещё 3 успешных проверки импорта и всех ракурсов.

Бюджет модели 25k взят из разрешения пользователя в задаче Blender; текущее значение 21 114. Лимит canvas остаётся ~1 Мп. Общая production-сборка со стендом и просмотрщиком — около 6,65 МБ без сжатия, оценка gzip 1,85 МБ. В dist включены только активные GLB v006; исходники и старые версии сохраняются в рабочем проекте.

### CI: отдельный лимит для четырёх PNG

Первый CI run 34396136389: 28 проверок прошли, один планшетный тест превысил общий лимит 45 секунд во время сохранения четырёх снимков. Trace подтвердил: загрузка страницы 97 мс, ожидание готовности модели 492 мс, проверки геометрии/материалов прошли; screenshot занимал примерно 8/14/12/10 секунд на программном рендерере CI. Для этого теста артефактов установлен лимит 90 секунд и scale=css при сохранении PNG. Проверки, размер canvas и требования к производительности приложения не ослаблены.
