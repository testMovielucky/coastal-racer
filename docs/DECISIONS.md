# Решения

## 2026-09-09 · Этап 0

1. Сохраняем стек плана: TypeScript 7.0.2, Vite 8.2.2, Babylon.js 9.25.0, Havok 1.3.14, Vitest 5.0.0, Playwright 1.63.0. Версии зафиксированы в package.json и package-lock.json. Совместимость Babylon/Havok подтверждена интеграционным тестом реального WASM и запуском production в Chrome.
2. Проверку Blender пропускаем по прямому указанию заказчика: Blender пока не установлен. Не устанавливаем и не запускаем его. Node в окружении: v24.19.0. npm 11.6.2 загружен локально в игнорируемую .tools; системные настройки не менялись.
3. Стенд намеренно содержит коробчатые кузова и фиксированную дорогу. Руление, газ, нитро, боты, генератор, экономика и сохранение не входят в этап 0.
4. Один экземпляр Havok WASM сохраняется между сбросами; мир, тела, формы, сцена и инструментация освобождаются при каждом сбросе. Физика 60 Гц с максимумом четырёх шагов за кадр. Публичный HavokPlugin.executeStep выполняет интеграцию и контакты, scene.physicsEnabled=false исключает второй автоматический шаг. Визуальные меши интерполируются отдельно от физических тел; собственный решатель физики не написан.
5. CPU work — время шага, интерполяции и JS-отрисовки/отправки команд, не время GPU. Диагностика обновляется дважды в секунду; окно до 1800 кадров плюс общие счётчики с последнего сброса. Пауза и подготовка исключены из кадровой статистики. Долгие кадры считаются от 25 мс; это диагностический порог, не критерий выпуска.
6. Статический пресет ограничивает canvas примерно одним мегапикселем, DPR не выше 2. Нет теней, текстур, частиц и постобработки. Автоматическое изменение качества по FPS пока не реализовано. Бюджеты выпуска из плана не меняются.
7. Ресурсы Havok загружаются через явный локальный Vite URL и fetch с тайм-аутом. Ошибка HTTP даёт экран повторной загрузки. WebGL1 не является запасным путём. При потере графического контекста стенд предлагает перезагрузку.
8. Потеря видимости, фокуса и альбомная ориентация сенсорного устройства требуют явного продолжения. На ПК сохраняется портретная рамка без блокировки альбомного монитора. Повторный запуск сохраняет состояние паузы.
9. GitHub Pages: относительный base './', без маршрутизатора/SPA fallback. Автотесты обслуживают production под /coastal-racer/ и проверяют отсутствие сторонних запросов. Это не проверка публичного домена или физического iOS-устройства.
10. Заказчик разрешил самостоятельно создать GitHub-репозиторий. Выбрано имя coastal-racer и публичный репозиторий для Pages. Реальный адрес/результат деплоя записывается в PROGRESS.

Основные API сверены с [Havok README](https://github.com/BabylonJS/havok), декларациями установленных пакетов и [Vite deployment guide](https://vite.dev/guide/static-deploy). Относительный путь дополнительно проверяется браузерными тестами.

## 2026-09-09 · Размер стенда на iPad

Заказчик сообщил о 60 FPS на стенде и узкой области на iPad. Причина: полноразмерная компоновка включалась только при ширине до 600 px, а более широкий iPad получал настольный лимит 460 px. На устройствах с основным сенсорным вводом стенд теперь занимает доступную область страницы (100% ширины, 100dvh высоты, fallback 100svh). На ПК остаётся портретная рамка. Панель диагностики на планшете ограничена 560 px по центру. Перспективу пересчитывает Babylon при resize; лимит canvas ~1 Мп не увеличен. Это исправление компоновки этапа 0, без Fullscreen API и без перехода к этапу 1.

Пользователь установил Blender самостоятельно. Наличие установки принято с его слов; версия/путь пока не проверены.

## 2026-09-09 · Просмотр принятой v006 в Babylon

По запросу пользователя подготовлена ограниченная проверка модели в Babylon: отдельный экран ?view=car-v006. Основной стенд и его физика сохранены; контроллер автомобиля и дальнейшие этапы не реализуются. glTF-loader закреплён на 9.25.0, как core. Реестр npm не отвечал с этого компьютера; пакет установлен через registry.yarnpkg.com для разработки, lockfile сохраняет точные версии/хеши и канонические npm URL. Runtime CDN не добавлены.

Используется принятый неизменённый GLB v006 с проверкой SHA-256 при сборке и загрузке. PBR-материалы, COLOR_0, иерархия, метры и локальная X колёс сохранены. Сцена right-handed, +Z вперёд. Освещение тестовое: направленный свет, заполнение и локально вычисленная небольшая cubemap; это не финальное побережье. Вращение колёс только визуальное, коллайдер показывается рамкой без подключения физики.

Vite копирует в dist только выбранные GLB v006. Прошлые версии и исходники не удалены. Бюджет модели остаётся ранее одобренным 25k, canvas ~1 Мп. Подробности, фактические проверки и ограничения — docs/CAR_V006_BABYLON.md.
